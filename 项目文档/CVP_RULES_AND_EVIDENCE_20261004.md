# 当前 CVP 规则与证据（2026-10-04）

官网鼓励合法防御用途受到防护影响者申请 CVP，禁止用途不解禁。真实用途及所受影响应如实说明；公开说明未列仓库白名单、最低数量或必附原始拦截记录的要求，本复核不设置日志门槛。模型适用范围按 [官方当前说明](https://support.claude.com/en/articles/14604842-real-time-cyber-safeguards-on-claude-opus-and-sonnet)核对。

申请人说明本轮渠道为 **Claude.ai / Claude Code**。第一方渠道从 Verification Portal 申请，需身份验证，申请选项只对授权管理员可见；实际账号与权限尚未查看。原始记录可选，缺少它不等于官方不合格，项目发布也不代表获批。

GitHub 的维护名和管理权限不能替代真实身份、组织或 Anthropic 权限。身份验证通过实际官方流程完成；这里不收集证件、自拍或凭据。见 [身份验证说明](https://support.claude.com/en/articles/14328960-identity-verification-on-claude)。

若实际使用 Console/API 工作区，再按其组织 grant、管理员权限及 Qualifications/Active 核对，不能机械套成 Claude.ai 申请的额外表单要求。CVP 官方主说明当前写明 ZDR 组织暂不符合参与条件；工作区数据保留设置不能当成已获 CVP 资格。一般防护页面和工作区规则的关系须结合真实渠道、组织资格判断。见 [工作区 program 说明](https://support.claude.com/en/articles/16764810-assign-a-program-to-workspaces-in-claude-console)及 [工作区保留说明](https://support.claude.com/en/articles/16824617-turn-on-data-retention-for-a-workspace-in-a-zero-data-retention-organization)。

所有用途继续受 [Anthropic 使用政策](https://www.anthropic.com/legal/aup)约束。用途、授权和贡献必须真实，不能把他人材料改名后宣称全部原创。

这次逐项复核整理的是项目附件，实际账号资格及批准结果尚未核实。材料应如实说明自己的工作、合法目的、授权范围和相关功能；已有防护影响时可说明实际情况及选附佐证。一项真实任务可以关联多个附件。这是我们的整理方案，不把每仓原始请求/响应或 API 工作区状态写成统一的官方必填字段。

2026-10-02 的规则、测试和发布记录保留为历史。当前工程范围见 [91 软件与 3 资料逐项矩阵](CVP_REVIEW_20261004.md)。本次没有重新执行安全实现或完成全量代码审计，也没有核实真实申请账号或批准结果。
