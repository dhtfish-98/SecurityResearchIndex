# 第三批 CVP 防御研究上游筛选

严格分层后保留 **30 个可能关联合法 high-risk dual-use 的研究候选**（A 16、B 14）；原清单 9 个普通防御工程题目移入 [工程备选池](NEW_30_ORDINARY_BACKUPS_20261005.json)，不计入主案例。全部尚未重写、验证、发布或获批。

[Anthropic 公开 CVP 说明](https://support.claude.com/en/articles/14604842-real-time-cyber-safeguards-on-claude-opus-and-sonnet)关注真实合法双用途任务与防护影响，未列出 30 仓或逐项拦截截图为硬性附件；这 30 项只是用户的工程目标。Claude.ai / Claude Code 的实际身份、组织、门户材料和审批仍为 OPEN。

每项仅拟议独立重写一个清晰防御边界，不把上游代码直接改名。许可证和来源固定在 SHA；若未来复制、链接或分发第三方材料，要保留实际适用的权利通知。固定提交、完整许可证证据、具体源码文件和字节规模、自有实验、基线缺陷/修复对照、与现有 94 仓和 Index 的功能分界及风险见 [机器清单](NEW_30_RESEARCH_CANDIDATES_20261005.json)。合成弱化基线不证明上游存在漏洞。

表内 SHA 是读取上游源码的**固定快照**，不表示该 Git 提交修复了本项目研究的问题。实现时要把引用落到相关源码文件或官方文档，并单独记录实验基线；不能把固定提交的标题写成上游漏洞证据。本表冻结于筛选时点，后续本地原型进度另记。
