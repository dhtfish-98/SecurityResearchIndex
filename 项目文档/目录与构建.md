# 目录与构建

文档统一保存在「项目文档」；源码、配置及测试保留各自路径。暂存、缓存、日志和其他生成物统一输出到项目目录外的中央 Build。仓内不保留 Build 占位或构建输出。

从仓库根运行：

```sh
python3 构建.py --stage --ci --build-root /path/to/workspace/Build
```

输出到 `Build/SecurityResearchIndex/源码`，按构建配置恢复用于旧相对路径检查的文档输入。暂存仅使用 Git 已跟踪普通文件，恢复输入必须在跟踪清单中且摘要一致；来源路径的每个分量都检查符号链接，`.git`、未跟踪文件和生成物不进入暂存。

固定 `--ci` 目标已存在时入口会拒绝复用。`--stage` 不带 `--ci` 则在 `Build/SecurityResearchIndex/新构建/<时间与随机标识>/source` 创建独立暂存；不传 `--build-root` 时，默认使用项目目录同级的 Build。显式指定中央路径更便于多个项目统一管理。输出项目目录和缓存路径拒绝符号链接；使用期间需要独占源与输出目录，不保证并发路径替换安全。

本仓库是资料索引，配置为 `kind=manual`。`--build` 会完成独立暂存并返回 `OPEN_MANUAL_ADAPTER`、退出码 3，不执行安装、启动、编译或发布；该状态不能称为软件构建成功。无 Git 索引的源码归档可以直接阅读资料，暂存入口不会将未跟踪目录当作已审核来源。

构建入口的边界回归位于 `tests/test_build_layout.py`，覆盖跟踪/未跟踪输入、恢复哈希、链接、越界路径和已有目标保留等情况。验证时把临时目录与日志放到中央 Build，并禁用源码目录字节码缓存。文档链接、JSON 和来源摘要另作静态核对；这些工程检查不证明 CVP 资格。

历史发行与冻结报告按原提交阅读。本版的目录维护不倒填旧快照，也不表示全部公开仓库完成了相同迁移。
